# shortener

Сервис сокращения ссылок на Go с REST API и PostgreSQL. Предназначен для создания
коротких ссылок, перенаправления на исходный URL и подсчёта переходов.

Приложение создаёт ссылки, перенаправляет по короткому коду и возвращает статистику.
Docker Compose запускает PostgreSQL, отдельную команду миграций и HTTP API.
GitHub Actions проверяет код и интеграцию с PostgreSQL на каждом PR в `main`
и push в `main`. [План разработки](docs/PLAN.md).

## Быстрый старт

Требования: Git, curl, Docker с запущенным движком и Docker Compose v2.
Для локального запуска без контейнера API также нужен Go 1.27.0
(см. [go.mod](go.mod)). Команды ниже выполняются
в Bash; на Windows используйте Git Bash. Если репозиторий уже клонирован,
перейдите в его корень и пропустите первые две команды. Остальные команды
выполняются из корня репозитория.

```bash
git clone https://github.com/uneronnik/shortener.git
cd shortener
cp -n .env.example .env
```

В `.env` задайте свой локальный пароль в `POSTGRES_PASSWORD` и тот же пароль
в `DATABASE_URL` и `DOCKER_DATABASE_URL`. В URL специальные символы пароля
должны быть URL-encoded. Не меняйте хост `db` в `DOCKER_DATABASE_URL`: это имя
сервиса внутри Compose; `DATABASE_URL` с `localhost` используется Go-командами
на компьютере. Если `.env` уже существовал, добавьте недостающие переменные
из [.env.example](.env.example): `cp -n` сохраняет существующий файл и не добавляет
в него новые строки. Затем выполните:

```bash
docker compose up --build -d --wait
curl -i http://localhost:8080/healthz
```

Compose ждёт готовности БД, применяет миграции отдельным контейнером и запускает
API только после их успешного завершения. `/healthz` возвращает `200 OK` с телом
`ok`; этот маршрут не проверяет подключение к БД на каждом запросе.
Команда `docker compose ps -a` должна показывать `api` и `db` как `healthy`,
а `migrate` — как `Exited (0)`: команда миграций завершается после выполнения.

Если используете PowerShell, создайте `.env` без перезаписи существующего файла
следующей командой, затем настройте его и запустите Compose, как описано выше:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Остальные примеры команд в README рассчитаны на Git Bash. `/healthz`, статистику
и короткую ссылку можно открыть в браузере; создание ссылки требует POST-запроса.

Создайте ссылку и скопируйте `code` из JSON-ответа (`201 Created`):

```bash
curl -i -H 'Content-Type: application/json' \
  -d '{"url":"https://go.dev"}' http://localhost:8080/links
```

Например, для ответа `{"code":"aB3xY7z","short_url":"http://localhost:8080/aB3xY7z"}`
адрес статистики будет `http://localhost:8080/links/aB3xY7z`.
В командах ниже замените `CODE` на код из своего ответа:

```bash
curl -i http://localhost:8080/CODE
curl -i http://localhost:8080/links/CODE
```

Первый запрос возвращает `302` с `Location: https://go.dev` и увеличивает счётчик;
второй возвращает JSON со статистикой, включая `clicks: 1`. Не добавляйте `-L`,
если хотите увидеть сам редирект. При смене внешнего порта `PORT` обновите
`BASE_URL` и адреса запросов.

Логи: `docker compose logs api migrate`. Остановка с сохранением ссылок:
`docker compose down` (без `-v`). Данные находятся в именованном Docker volume.
API работает от непривилегированного пользователя; при остановке даёт активным
запросам до 5 секунд. Логи в формате JSON выводятся в stdout.

### Если запуск не удался

- `DOCKER_DATABASE_URL is missing a value`: проверьте, что в сохранённом `.env`
  есть непустая строка `DOCKER_DATABASE_URL`. Если файл создан раньше, добавьте
  недостающие настройки из `.env.example`, сохранив текущие учётные данные.
- `migrate` завершился с кодом `1`: выполните `docker compose logs migrate`.
  Если в ошибке подключения указан `localhost`, исправьте хост в
  `DOCKER_DATABASE_URL` на `db`, порт — на `5432`. Внутри контейнера `localhost`
  указывает на сам контейнер, а не на сервис PostgreSQL.
- Ошибка аутентификации PostgreSQL: проверьте совпадение пароля в обоих URL
  и `POSTGRES_PASSWORD`. Если volume уже существует, нужен пароль, с которым
  база была создана; изменение `.env` не меняет его в БД.

После исправления `.env` повторите `docker compose up --build -d --wait`.

## PostgreSQL и миграции

Если `.env` ещё нет, скопируйте пример:

```bash
cp -n .env.example .env
```

Перед продолжением задайте в `.env` свой локальный пароль в `POSTGRES_PASSWORD`
и тот же пароль в `DATABASE_URL` и `DOCKER_DATABASE_URL`. Специальные символы
в пароле внутри URL должны быть URL-encoded; значения с символами, значимыми
для Bash, заключайте в одинарные кавычки. При изменении пользователя или имени
БД обновите оба URL. При смене `POSTGRES_PORT` обновите порт в `DATABASE_URL`;
внутри Compose PostgreSQL по-прежнему доступен на порту 5432.
`.env` исключён из Git.

```bash
set -a
source .env
set +a
docker compose up -d --wait db
go run ./cmd/migrate
```

Compose читает `.env` автоматически. Go-команды получают настройки из окружения,
поэтому перед ними нужен `source` с экспортом переменных. После изменения `.env`
повторите экспорт в терминале, где запускаете команды.

Команда миграций создаёт таблицу `links` и записывает версию схемы через goose.
Повторный запуск применяет только новые миграции и сохраняет существующие ссылки.
SQL встроен в команду при сборке; API сам миграции не запускает.
Запускайте одну команду миграций за раз. Подробности — в
[решении о миграциях](docs/adr/0001-database-migrations.md).

PostgreSQL доступен только через loopback на `POSTGRES_PORT` (по умолчанию 5432).
Данные сохраняются в именованном Docker volume. Начальные учётные данные
применяются только при создании пустого volume: редактирование `.env` не меняет
пароль уже созданного пользователя БД.

Остановить БД с сохранением данных:

```bash
docker compose stop db
```

Для локального запуска API после миграций выполните `go run ./cmd/shortener`
в терминале с экспортированным `.env`. Освободите порт, если контейнер API
уже запущен: `docker compose stop api`. Go-приложение само `.env` не читает.
`DATABASE_URL` обязателен; при старте API проверяет соединение с БД
с таймаутом 5 секунд. При ошибке конфигурации или подключения процесс
завершается с ненулевым кодом. Миграции при старте API не выполняются.

## HTTP-контракт

Операции доступны в запущенном приложении. HTTP-хендлеры проверяются через `httptest`.

| Метод и путь | Запрос | Успешный ответ |
|---|---|---|
| `POST /links` | JSON: `{"url":"https://go.dev"}` | `201`, JSON с `code` и `short_url` |
| `GET /{code}` | Код ссылки в пути | `302`, заголовок `Location` с исходным URL; +1 к счётчику |
| `GET /links/{code}` | Код ссылки в пути | `200`, JSON с `url`, `code`, `clicks`, `created_at` |

Допускаются только абсолютные HTTP/HTTPS URL. Код содержит 7 символов base62
и генерируется через `crypto/rand`. При конфликте кода сервис выполняет
не более трёх попыток сохранения.

Тело POST ограничено 1 МиБ и должно содержать ровно один JSON-объект.
Некорректный URL или тело запроса дают `400`, отсутствующая ссылка — `404`,
внутренняя ошибка — `500` без раскрытия деталей. Ошибки операций возвращаются
в JSON с полем `error`.

Чтение заголовков и тела запроса ограничено `HTTP_READ_TIMEOUT`; заголовки
дополнительно ограничены пятью секундами. При таймауте чтения тела сервер
возвращает `408` с `{"error":"request body timeout"}`, если соединение ещё доступно.
На вызов сервиса после разбора тела выделяется `OPERATION_TIMEOUT`, включая
ожидание соединения из пула и выполнение SQL. При истечении этого времени
API возвращает `503` с `{"error":"operation timed out"}`. Отключение клиента
отменяет контекст операции; отправить ответ отключившемуся клиенту нельзя.

Таймаут или потеря соединения не гарантируют, что запись не была выполнена:
создание ссылки или увеличение счётчика могли завершиться до отмены.
Автоматический повтор такого запроса может создать ещё одну ссылку или переход.

Внутренние ошибки записываются через `slog` в stdout: `operation` содержит
`shorten`, `resolve` или `stats`, `reason` — безопасную категорию причины
(`deadline_exceeded`, `network_error`, `postgres_` с SQLSTATE,
`code_collision_exhausted`, `operation_canceled` или `internal_error`).
Исходный текст ошибки, URL, тело запроса и учётные данные не записываются.
Ожидаемые `400`/`404` и отключения клиента не логируются как внутренние сбои.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | Порт локального HTTP-сервера; в Compose — внешний порт, внутри контейнера всегда 8080 |
| `DATABASE_URL` | Нет, обязательна | Подключение API и команды миграций к PostgreSQL при локальном запуске |
| `DOCKER_DATABASE_URL` | Нет, обязательна для Compose | URL с хостом `db` и портом 5432; Compose передаёт его контейнерам как `DATABASE_URL` |
| `BASE_URL` | `http://localhost:8080` | Префикс для `short_url`; не меняет адрес прослушивания |
| `HTTP_READ_TIMEOUT` | `5s` | Общее время чтения заголовков и тела одного HTTP-запроса |
| `OPERATION_TIMEOUT` | `3s` | Бюджет вызова сервиса, включая ожидание пула и SQL |
| `HTTP_WRITE_TIMEOUT` | `10s` | Срок записи ответа от окончания чтения заголовков |
| `POSTGRES_USER` | Нет, обязательна в Compose | Пользователь БД при инициализации volume |
| `POSTGRES_PASSWORD` | Нет, обязательна в Compose | Пароль БД при инициализации volume |
| `POSTGRES_DB` | Нет, обязательна в Compose | Имя БД при инициализации volume |
| `POSTGRES_PORT` | `5432` | Локальный порт PostgreSQL |
| `TEST_DATABASE_URL` | Нет | Подключение для интеграционных тестов |

Значения в [.env.example](.env.example) — пример локальной конфигурации.
При смене `PORT` значение `BASE_URL` автоматически не меняется.

Таймауты задаются положительными длительностями Go, например `500ms` или `5s`.
`HTTP_WRITE_TIMEOUT` должен быть строго больше суммы `HTTP_READ_TIMEOUT` и
`OPERATION_TIMEOUT`, чтобы оставалось время на отправку ответа. Неверное значение
или соотношение останавливает API при запуске; значение настройки в ошибку не попадает.
Таймаут записи ограничивает сетевую запись, а дедлайн контекста — операции сервиса.
Простаивающие HTTP-соединения закрываются через 60 секунд.

## Проверки

```bash
go vet ./...
go test ./...
```

Домен и сервис тестируются без БД и HTTP, хендлеры — через `httptest`.
Без `TEST_DATABASE_URL` интеграционные тесты пропускаются.

В GitHub Actions выполняются `go vet ./...` и `go test ./... -count=1 -v`.
Версия Go берётся из `go.mod`; отдельный сервис PostgreSQL 17 и заданный
`TEST_DATABASE_URL` обеспечивают запуск интеграционных тестов миграций и
репозитория. Проверка в PR называется `Go checks` и обязательна для слияния
в `main`; ветка PR должна быть актуальна относительно `main`.

Для проверки миграций и репозитория запустите локальную БД и экспортируйте `.env`, как описано
выше, затем выполните:

```bash
TEST_DATABASE_URL="$DATABASE_URL" go test ./... -count=1
```

Интеграционные тесты создают и удаляют собственные схемы, проверяют ограничения
таблицы и повторное применение миграций с сохранением данных. Тесты репозитория
проверяют сохранение и чтение ссылок, конфликты кодов, отсутствующие ссылки,
параллельный подсчёт кликов и отмену операций через контекст. Пользователю БД
нужны права `CREATE SCHEMA`. Используйте локальную или тестовую БД.

Дополнительные проверки воспроизводят таймаут медленного тела через TCP,
истечение дедлайна операции, ожидание занятого пула и отмену SQL при блокировке
строки. Тесты логирования проверяют отсутствие чувствительных данных.

### Ручная проверка приложения

После быстрого старта проверьте полный сценарий:

1. Создайте ссылку через `POST /links`: ответ `201`, код из 7 символов и
   `short_url`. До первого перехода `GET /links/CODE` возвращает `clicks: 0`.
2. Вызовите `GET /CODE` через `curl -i` без `-L`: ответ `302`, заголовок
   `Location` содержит исходный URL. Статистика теперь возвращает `clicks: 1`.
   Каждый следующий запрос редиректа увеличивает счётчик ещё на один.
3. Проверьте отказы следующими командами: ожидаются `400`, `400`, `404` и `404`.

   ```bash
   curl -i -H 'Content-Type: application/json' -d '{"url":"ftp://example.com"}' http://localhost:8080/links
   curl -i -H 'Content-Type: application/json' -d '{"url":' http://localhost:8080/links
   curl -i http://localhost:8080/missing
   curl -i http://localhost:8080/links/missing
   ```

4. Запомните код и число переходов. Выполните `docker compose down` **без `-v`**,
   затем `docker compose up -d --wait`. Запросите статистику по тому же коду:
   ссылка и счётчик должны сохраниться. Флаг `-v` удаляет volume с данными.

## Структура

- `cmd/shortener` — запуск HTTP-сервера и корректная остановка.
- `cmd/migrate` — отдельная команда миграций.
- `internal/link` — сущность, валидация URL, генерация кода, сценарии и интерфейс хранилища.
- `internal/httpapi` — маршруты, JSON и преобразование доменных ошибок в HTTP-ответы.
- `internal/postgres` — репозиторий на `pgxpool`; счётчик увеличивается одним `UPDATE ... RETURNING url`.
- `migrations` — SQL-миграции, встроенные через `embed.FS`.
- [docs/adr](docs/adr) — принятые архитектурные решения.
