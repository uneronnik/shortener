# shortener

Сервис сокращения ссылок на Go: создаёт короткий код для URL, перенаправляет по нему и считает переходы.

> Статус: в разработке, план — в [docs/PLAN.md](docs/PLAN.md).

## Запуск

Сейчас реализован HTTP-скелет: `GET /healthz` возвращает `200 OK` с телом `ok`.
Локальный запуск (Git Bash):

```bash
PORT=8080 go run ./cmd/shortener
curl -i http://localhost:8080/healthz
```

Ctrl+C запускает корректную остановку: сервер даёт активным запросам до 5 секунд.
Логи в формате JSON выводятся в stdout.

Домен и сервисный слой реализованы: валидация URL, генерация кода, создание ссылки
с максимум тремя попытками сохранения при коллизиях, получение URL с увеличением
счётчика и просмотр статистики. Сервис проверяется unit-тестами с фейковым
репозиторием.

HTTP-слой реализован и проверен через `httptest`: `POST /links` возвращает 201
с `code` и `short_url`, `GET /{code}` — редирект 302, `GET /links/{code}` —
статистику. Ответы операций и ошибок имеют формат JSON (кроме успешного редиректа);
доменные ошибки преобразуются в 400/404, внутренние — в 500 без раскрытия деталей.
Тело POST ограничено 1 МиБ и должно содержать ровно один JSON-объект.
`BASE_URL` читается из окружения, завершающий `/` убирается при сборке короткой ссылки.

В запускаемом приложении пока подключён только `/healthz`: PostgreSQL добавляется
на шагах 5–6, а реальный сервис передаётся HTTP-хендлеру при сборке на шаге 7.
Промежуточное хранилище в памяти не используется.

Docker Compose и примеры запросов ниже станут доступны в запускаемом приложении
после сборки целиком на шаге 7.

```bash
docker compose up --build
```
API доступен на `http://localhost:8080`.

## Примеры
```bash
# create a short link
curl -i -X POST http://localhost:8080/links -d '{"url":"https://go.dev"}'
# → 201 {"code":"aB3xK9q","short_url":"http://localhost:8080/aB3xK9q"}

# follow it
curl -i http://localhost:8080/aB3xK9q
# → 302 Location: https://go.dev

# stats
curl http://localhost:8080/links/aB3xK9q
# → {"code":"aB3xK9q","url":"https://go.dev","clicks":1,"created_at":"..."}
```

## Конфигурация
| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `8080` | Порт HTTP-сервера |
| `DATABASE_URL` | — | Строка подключения к PostgreSQL |
| `BASE_URL` | `http://localhost:8080` | Префикс для `short_url` |

## Архитектура
- `internal/link` — домен: сущность, валидация, генерация кода, сценарии
- `internal/httpapi` — HTTP-слой, без бизнес-логики
- `internal/postgres` — хранилище на pgx
- `cmd/shortener` — сборка и запуск, `cmd/migrate` — миграции

## Тесты

Разработка ведётся по TDD: сначала падающий тест на ожидаемое поведение,
затем минимальная реализация, после — рефакторинг с проходящими тестами.
Домен и сервис тестируются без БД и HTTP, хендлеры — через `httptest`.

```bash
go test ./...                                   # unit
TEST_DATABASE_URL=postgres://... go test ./...  # + integration
```
