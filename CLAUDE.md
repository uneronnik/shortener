## Структура (лёгкий DDD в стиле Go)
- `cmd/<app>/main.go` — точка входа, только сборка зависимостей и запуск
- `internal/<домен>/` — пакет на каждую предметную область (`order`, `user`), а не на слой
  - `order.go` — сущности и бизнес-правила; не знает про HTTP, SQL и JSON
  - `service.go` — сценарии использования (создать заказ, отменить заказ)
  - `repository.go` — интерфейс хранилища, объявленный здесь, где он используется
- `internal/postgres/` — реализация репозиториев
- `internal/httpapi/` — хендлеры: разбор запроса → вызов сервиса → ответ
- Никаких пакетов `utils`, `common`, `helpers`

## Разработка
- TDD: сначала падающий тест, потом минимальная реализация, потом рефакторинг
- Доменная логика тестируется unit-тестами без БД и HTTP
- Хендлеры тестируются через `net/http/httptest`

## Правила
- Ошибки возвращаются, а не паникуют. Оборачивать с контекстом: `fmt.Errorf("load user %d: %w", id, err)`
- `context.Context` — первый параметр у функций с I/O
- Интерфейсы объявляются там, где используются, и только когда нужны (не «на будущее»)
- Конфигурация через переменные окружения, секреты только в `.env` (он в .gitignore)

## Принципы 12-factor (https://12factor.net/) — для HTTP-сервисов
- Конфиг только из переменных окружения, без хардкода адресов и паролей (III)
- БД, кэш, очереди — внешние ресурсы по URL из env; сменить базу = сменить переменную (IV)
- Процесс без состояния: ничего важного в памяти и на локальном диске между запросами (VI)
- Порт из env (`PORT`), сервис сам слушает порт (VII)
- Быстрый старт и graceful shutdown по SIGINT/SIGTERM через `signal.NotifyContext` (IX)
- Локально всё поднимается через Docker Compose, как можно ближе к «проду» (X)
- Логи через `log/slog` в stdout, никаких лог-файлов из приложения (XI)
- Миграции и разовые задачи — отдельной командой (`cmd/migrate`), а не при старте сервиса (XII)
- Для CLI-утилит большая часть этого не нужна: не усложняй
